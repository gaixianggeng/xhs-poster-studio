# 小红书封面生成器：项目上下文

> 此文档记录网站设计决策；最新线上部署事实见 [DEPLOYMENT.md](./DEPLOYMENT.md)
> 来源：基于当前可见会话和现有代码提炼，不是聊天全文
> 最后更新：2026-10-12

## 1. 目标

### 要解决的问题

为小红书科技、效率工具、AI 开发和移动开发内容提供一个轻量的「实测笔记」封面生成器，用固定骨架保持主页统一，减少重复调整标题、间距、配色和导出尺寸的成本。

### 目标用户与使用场景

- 主要用户：需要持续发布同一视觉系列封面的内容创作者。
- 使用场景：修改一期封面的主词、标题、实测条件、证据和结论，实时检查海报与双列列表中的效果，然后导出可发布 PNG。

### 预期结果与验收标准

- 页面无需安装依赖即可通过静态服务器运行。
- 文案、配色和核心版式修改后立即反映在预览中。
- 固定使用小红书图文封面 3:4 竖版格式，导出 1080 × 1440 PNG。
- 6 张示例、6 种证据类型和 6 套配色都能直接渲染，文字不溢出、结论章不遮挡证据内容。
- 海报与双列信息流预览使用同一份实时渲染结果。
- 导出的 PNG 固定为 1080 × 1440。
- 刷新页面后保留本地设置，不上传文案或图片。
- 临时 IP 地址可正常访问；正式域名在完成备案或火山引擎接入备案后恢复 HTTPS 访问。

## 2. 方案

### 已确认方案

2026-10-12 起，旧的单一大字报版式（模块开关、17 组配色、固定 84% × 88% 卡片外轮廓、照片区域缩放）整体替换为「实测笔记」版式。旧版式最后一次提交为 `1bcb7e1`，替换前的未提交改动另存为本地 `git stash`。

- 设计来源：对标账号的封面每篇画风不同，但信息层级、画面密度和讲解方式稳定。本账号的定位是「亲手实测」，所以统一感来自固定骨架，画面随证据变化。
- 骨架固定为七项：报告头（深色胶囊 + 系列 · 日期）、主词（主色超大字，可带中文后缀）、两行标题（【】标出唯一关键词，放进主色胶囊）、实测条件胶囊（最多 3 个）、证据窗（白底圆角，跨在两块颜色之间）、结论章（波浪饼干形，斜盖在证据窗右上角）、页脚。
- 证据窗只放一个证据，提供截图、步骤、分层、对比、评分、大字 6 种类型；各类型字段分开保存，切换类型不清空内容。截图按 cover 方式铺满证据区，在预览上拖动调整取景。
- 配色参考 Android 16（Material 3 Expressive）：浅色底 + 另一色底带 + 同色系深色文字 + 一个高饱和主色 + 一个点缀色。共 6 套（樱粉、薄荷、青柠、天蓝、薰衣草、杏黄），色值自行调配，不是官方色板。
- 深浅两档：封面默认「深一档」，只把底色和底带加深一级，在白色信息流的缩略图里更突出；内页用「标准」浅色，更清新。两档的文字、主色和点缀色相同。
- 形状使用圆的并集绘制（结论章饼干形、花瓣与四叶草贴纸），不引入图片素材；主词伸到贴纸位置时不画对应贴纸。
- 结论章圆心固定在证据窗顶边上方 14 px；有结论章时实测条件胶囊行宽限制为 668 px，提前换行，避免被章遮挡。
- 只用系统字体：主词 Arial Black，标题 Helvetica Neue + 苹方，等宽 SF Mono / Menlo。网站部署在国内服务器，Google Fonts 不可用；字形与设计稿（Archivo、Noto Sans SC、JetBrains Mono）会有差别。
- 6 张示例取自已发布或已定时的笔记，载入时整体替换文案，可撤回一次。
- 主页双列预览可加载已发布封面快照、用当前文案生成的 6 套配色和本地旧封面。
- 品牌名称采用官方大小写 `Codex`。

### MVP 范围

- 单张封面编辑，固定「实测笔记」骨架。
- 6 种证据类型、6 套配色、封面 / 内页两档深浅、贴纸开关。
- 可选本地截图上传与证据区内拖动取景。
- 小红书图文标准 1080 × 1440 画布。
- 海报预览、主页对比和 PNG 导出。
- 浏览器 `localStorage` 自动保存。
- 静态网站部署、临时 IP 访问和正式域名 HTTPS 配置。

### 明确不做

- 账号系统、团队协作和云端存储。
- 后端 API、数据库和服务端图片生成。
- 模板市场、批量生成、自定义字体上传，以及骨架元素的自由拖拽排版。
- 人物抠图、滤镜、插画、二维码、纹理、渐变、投影或 3D 元素等高级素材编辑能力；贴纸只保留两种固定形状。

### 关键流程

1. 从示例开始，或直接写文案：报告头、主词、两行标题、实测条件、结论章和页脚。
2. 选证据类型并填写内容；截图类型选择本地图片后在预览上拖动取景。
3. 选配色方案与深浅：封面用「深一档」，内页用「标准」。
4. 切到主页预览，加载已发布封面或 6 套配色检查协调度。
5. 导出 1080 × 1440 PNG，放入运营项目的单篇笔记目录。

## 3. 实现

### 技术栈与选择理由

- 原生 HTML、CSS、JavaScript：功能规模小，无需构建工具，部署和维护成本最低。
- Canvas 2D：让页面预览与 PNG 导出复用同一渲染路径。
- `localStorage`：满足单用户本地保存，不引入账号和后端。
- Nginx + HAProxy：沿用服务器现有入口和 SNI 分流方式，不新增服务。

### 架构与运行方式

```text
index.html      页面结构与编辑控件
styles.css      工作台、响应式布局和列表预览样式
app.js          实测笔记骨架、6 种证据、配色与深浅、截图取景、Canvas 渲染、主页对比和导出
deploy/nginx/   域名入口配置与临时 IP 路径配置片段
docs/          网站项目上下文、部署说明与历史设计截图
../xhs-poster-studio/  独立的小红书运营项目；网站导出的 PNG 按笔记存放在那里
```

本地运行：

```shell
python3 -m http.server 4173
```

生产环境为腾讯云上的静态站点 `https://xhs.code89757.com`，文件位于 `/var/www/xhs-poster-studio`，由 Nginx 提供 HTTPS。2026-09-11 之前部署在火山引擎，旧域名 `poster.code89757.com` 因备案校验阻断已下线。服务器地址、登录方式与备份路径只记录在本地的 `docs/DEPLOYMENT.local.md`，不入库。

完整发布和回滚步骤见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

### 数据、API 与外部集成

- 无后端 API、数据库和服务端状态。
- 文案与样式保存在 `localStorage` 的 `xhs-poster-studio:field-note:v1`（旧版式的 `xhs-poster-studio:v1` 不再读取）；截图和主页对比封面仅保存在页面运行时内存，刷新后需要重新选择。
- 截图文件上限为 20 MB，不上传服务器。
- 正式域名：[https://xhs.code89757.com](https://xhs.code89757.com)。
- 静态资源使用版本查询参数规避一小时浏览器缓存导致的新旧脚本混用。

## 5. 假设与待确认项

### 合理假设

- 在出现明确的多人协作或跨设备同步需求前，项目继续保持纯静态、单用户、本地状态模式。
- 下一阶段优先提高稳定性和可回归验证能力，而不是立即扩展模板市场或账号体系。

### 待确认项

- 后续产品优先级尚未确定：自动化回归测试、模板保存，还是部署自动化。
- 历史封面目前只用于本次主页对比；达到高频使用后，再决定是否增加本地模板保存或批量生成。

### 当前阻塞

- 正式域名尚未完成 ICP 备案，或已有备案但未完成火山引擎接入备案，因此无法从公网正常访问。
- 临时 IP 地址不受该域名校验影响，当前可用。

## 6. 风险与优化

### 当前风险

- 系统字体在不同操作系统上的字形和测量结果可能略有差异；Yozai 加载失败时会回退系统字体。
- 3:4 标准画布尚未建立自动化视觉回归测试。
- 单一 Canvas 布局依赖浏览器字体测量，需要增加固定文案与超长文案的视觉快照。
- 状态只存在当前浏览器；清理站点数据后无法恢复。
- 照片刷新后需要重新选择；超大图片会增加浏览器内存占用。
- 静态资源有一小时缓存，发布时必须同步更新资源版本参数。
- 临时 IP 地址仅使用 HTTP，不适合作为长期正式入口。
- 正式域名依赖备案状态同步到火山引擎，单纯修改 DNS、证书、Nginx 或 HAProxy 无法解除阻断。
- 部署仍依赖人工同步文件和人工验收。

### 后续优化（不进入当前 MVP）

- 抽离布局计算为可测试的纯函数，增加 Node 内置测试。
- 增加少量固定视觉快照，覆盖主要模块组合的 3:4 海报和双列主页预览。
- 增加模板保存、导入和导出，但继续保持本地优先。
- 当发布频率足够高时，再增加最小化的部署脚本和版本号自动更新。

## 7. 下一步

1. 抽离布局和截图裁切计算为纯函数，使用 Node 内置测试覆盖海报与双列信息流缩略图。
2. 为静态资源版本参数增加一个无依赖的发布前更新脚本，减少旧缓存导致的脚本错配。
